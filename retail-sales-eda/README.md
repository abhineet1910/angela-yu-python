# Retail Sales EDA & Dashboard

A basic-level data science project: exploratory data analysis on retail sales
data using **pandas** and **seaborn**. Cleans a messy sales CSV, computes key
business metrics, and generates 4 charts summarizing performance.

## What it does

1. **Loads** a retail sales CSV with columns `[order_id, date, product, category, region, sales, profit]`
2. **Cleans** the data:
   - Removes duplicate rows
   - Standardizes inconsistent text casing (e.g. `"north"` → `"North"`)
   - Fills missing `profit` values using the category median (more accurate than a global fill)
   - Drops any row still missing critical fields
3. **Analyzes**:
   - Monthly sales trend
   - Top 5 products by total profit
   - Region-wise sales, profit, and order count
   - Overall revenue, profit, average order value, and profit margin
4. **Visualizes** — saves 4 charts to `outputs/`:
   - `1_monthly_sales_trend.png` — line chart of sales over time
   - `2_top5_products_by_profit.png` — bar chart of best-performing products
   - `3_region_sales_vs_profit.png` — grouped bar chart comparing regions
   - `4_profit_distribution_by_category.png` — box plot of profit spread per category

## How to run (PyCharm)

1. Open this folder as a new PyCharm project.
2. Create a virtual environment when prompted (or `File > Settings > Python Interpreter > Add`).
3. Open the terminal inside PyCharm and install dependencies:
   ```bash
   pip install -r requirements.txt
   ```
4. Run `analysis.py` (right-click → Run, or `python analysis.py` in the terminal).
5. Check the console output for the stats summary, and the `outputs/` folder for the 4 charts.

## Using your own dataset

This repo ships with a **synthetic** `retail_sales.csv` (generated by
`data/generate_data.py`) so the project runs immediately. To use a real
dataset instead — e.g. the "Superstore Sales Dataset" on Kaggle:

1. Download a CSV with (at minimum) `date, product, category, region, sales, profit` columns.
2. Replace `data/retail_sales.csv` with it (rename columns to match if needed).
3. Re-run `analysis.py`.

## Notes for the viva

- **Why fill missing profit with the category median instead of dropping rows or using the global median?**
  Profit margins differ significantly by category (e.g. Electronics vs Stationery), so the
  category median is a more realistic estimate than a single dataset-wide value, and it avoids
  losing usable rows.
- **Why `.title()` for text cleaning?** Real-world exports often have inconsistent casing
  (`"north"`, `"North"`, `"NORTH"`) that would otherwise be treated as different categories
  during grouping — this is a very common real-world data quality issue.
- **Why a box plot for category profit instead of a bar chart?** A box plot shows the spread
  and outliers within each category, not just the average — useful for spotting categories with
  inconsistent profitability.
